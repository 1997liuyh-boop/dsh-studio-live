# Live2D 形象接入

用户已要求按前述 ZIP 导入、口型、表情和 OBS 方案实施，并选择官方样例验证。

## 方案选择

采用内嵌浏览器渲染：复用现有形象预览和 OBS 地址，增加 Cubism 3/4 格式的模型 ZIP。外部 VTube Studio 桥接可以减少 SDK 分发要求，但需要另装软件且无法复用当前内嵌预览；官方 Framework 直接接入需要维护更多渲染代码。因此本地验证采用 pixi-live2d-display 的 Cubism4 入口和 PixiJS 6。

## 模型与渲染

宿主校验 ZIP 文件数、解压大小、相对路径、唯一 model3.json、MOC3 与贴图及动作引用。仅提供校验过的文件，不执行包内脚本，不访问外部模型地址，不播放模型自带声音。原始 ZIP 仍通过现有 IndexedDB 保存；工作室预览和只读 OBS 读取同一份宿主内存资源。

渲染器按需加载固定来源 Cubism Core 和构建产物，自动适配画布，限制 30fps，复用语音音量驱动口型。眨眼、呼吸和物理由模型参数决定；表情菜单展示模型真实提供的名称，不声称生成了模型缺失的表情。切换、关闭、失败时释放渲染器与纹理。图片和 VRM 的导入继续可用。

## 官方素材与发行

本地使用官方 Haru 样例，保留官方版权说明。Cubism Core 与样例放在 Git 忽略目录，仅用于本地开发验证。官方 SDK 发行页明确将 Expandable Application 排除于通常的小规模用户免费发行豁免；在确认本产品发行许可前，不发布含 Core 的公开包，也不自动替用户申请或同意发行合同。

## 验证

测试畸形 ZIP、路径穿越、外部引用、资源缺失、解压配额及模型声音剥离；验证图片与 VRM 兼容。桌面加载官方样例，检查嘴型随实际语音变化、可选表情、重新打开恢复，以及独立 OBS 页面同一模型显示。运行现有聚焦测试、构建、类型检查和安装包检查。没有 OBS 实机时，只验证浏览器叠加层。
